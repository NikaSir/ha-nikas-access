# Архитектура панели «Доступ»

## Владение маршрутом

Интеграция регистрирует только `dashboard-access-v1`. Перед регистрацией выполняется проверка существующего владельца. Идентификатор создавшей маршрут config entry сохраняется в `hass.data`; при выгрузке удалить маршрут может только эта же запись.

Статический каталог frontend регистрируется отдельно. Параметр версии в `module_url` обеспечивает cache-busting без цепочки исторических bundle-файлов.

## Поток состояния

1. Home Assistant передаёт новый объект `hass` в web component.
2. Панель один раз читает реестры устройств, сущностей и ярлыков и строит набор источников внутреннего и внешнего периметров.
3. Обновление состояний объединяется через `requestAnimationFrame`.
4. Меняются только текст, иконка, цветовой класс и доступность командных кнопок.
5. Постоянные Header, рабочая область, представления и нижнее меню не перестраиваются.

В периметры входят только `binary_sensor`, у которых на сущности или устройстве одновременно есть ярлык периметра и `v_ekspluatatsii`. Объекты с ярлыками обслуживания, замены, резерва или вывода из эксплуатации исключаются. Состояние считается закрытым только когда все найденные источники имеют фактическое значение `off`; любое иное значение, кроме `on`, становится «Нет данных».

Физическое положение секционных ворот вычисляется отдельной чистой функцией только из `binary_sensor.sensor_do_zb_15_16_contact`. Состояния обоих `cover` допускаются только для оценки доступности канала управления.

## Поток команды

1. Нажатие выбирает одну из шести заранее разрешённых команд.
2. Проверяется доступность канала управления.
3. Показывается подтверждение с объектом и действием.
4. После подтверждения ставится общий lock и отметка времени дедупликации.
5. Вызывается только `hass.callService("cover", service, {entity_id})`.
6. Успешный вызов показывает сообщение об отправке, но не меняет положение.
7. Ошибка сохраняется в постоянной плашке до явного закрытия пользователем.

## Будущий домофон

- `frontend/src/data/intercom.js` — возможности и будущие подтверждённые сущности;
- `frontend/src/views/intercom-view.js` — отдельное представление;
- `INTERCOM_MODULE.enabled` — явный флаг допуска реальных функций управления.

До модернизации `enabled` равен `false`, а `entityIds` остаётся пустым объектом. Внутреннее представление домофона видно как подготовленный модуль, но не содержит элементов управления. Планируемые возможности: связь, вызов, камера, открытие калитки или двери и история событий.

## Внутренняя навигация

Единственный зарегистрированный маршрут остаётся `/dashboard-access-v1/home`. Нижние кнопки меняют локальное состояние компонента между `statuses`, `gates`, `intercom` и `diagnostics`; они не вызывают навигацию Home Assistant и не добавляют записи в историю браузера. По умолчанию всегда открываются «Статусы».
