# NikaS Access

Автономная HACS-интеграция для панели Home Assistant **«Доступ»**. Панель управляет точками доступа дома и регистрируется независимо от YAML-панелей и основной панели «Дом».

- Название в боковом меню: **Доступ**
- Заголовок: **Контроль доступа**
- Маршрут: `/dashboard-access-v1/home`
- Возврат: `/dashboard-house-v12/home`
- Версия: `0.1.2`
- Стандарт интерфейса: NikaS v1.17

## Внутренние разделы

Нижнее меню принадлежит только панели «Доступ» и не ведёт в другие панели:

1. **Статусы** — главное представление с внутренним и внешним периметрами.
2. **Ворота** — управление секционными и распашными воротами.
3. **Домофон** — подготовленный экран без сущностей и команд до модернизации оборудования.
4. **Диагностика** — состояние реестров, привязок периметров, перечень входящих в расчёт устройств и датчиков, а также каналы управления воротами.

Переключение выполняется внутри web component, не меняет маршрут браузера и не перезагружает панель.

## Периметры

Entity ID периметров в репозитории не задаются. Панель читает реестры Home Assistant и находит действующие `binary_sensor` по ярлыкам:

- **Внутренний периметр** или **Внутренний контур**;
- **Внешний периметр**, **Наружный периметр**, **Внешний контур** или **Наружный контур**.

На сущности или её устройстве обязательно должен быть ярлык `v_ekspluatatsii`. Ярлыки `na_obsluzhivanii`, `trebuet_zameny`, `vyvedeno_iz_ekspluatatsii` и `rezerv` исключают объект из агрегата. `unknown`, `unavailable`, непривязанный ярлык и недоступный реестр показываются как **«Нет данных»**, а не как закрытый периметр.

## Ворота

### Секционные ворота

Физическое положение берётся **только** из:

`binary_sensor.sensor_do_zb_15_16_contact`

Управление выполняется через:

`cover.umnyi_kontroller_dlia_vorot_roximo_door`

Состояние `cover` не используется как подтверждение положения.

### Распашные ворота

Управление выполняется через:

`cover.umnyi_kontroller_dlia_vorot_roximo_2_door`

Физического датчика нет, поэтому панель постоянно показывает **«Положение не контролируется»** и не выводит предполагаемое открытое или закрытое состояние.

## Безопасность команд

Панель разрешает только следующие сервисы:

- `cover.open_cover`;
- `cover.stop_cover`;
- `cover.close_cover`.

Перед каждой командой открывается собственное окно подтверждения с явным названием объекта и действия. Во время отправки включается общий замок команд и выдерживается окно дедупликации. Ошибка не исчезает по таймеру: её можно убрать только отдельной кнопкой. Экранное положение ворот не меняется после нажатия и обновляется только фактическими состояниями Home Assistant.

## Архитектура

Разработка разделена на исходные модули в `custom_components/nikas_access/frontend/src/`. Сборка выпускает один автономный файл `nikas-access-panel.js`; Home Assistant загружает его со стабильного URL и параметром `?v=0.1.2`.

Модули будущего домофона выделены отдельно. Внутренняя вкладка показывает состояние подготовки, но `INTERCOM_MODULE.enabled` остаётся `false`, объект `entityIds` пуст, а команды отсутствуют до появления подтверждённого оборудования.

## Установка из принятой версии через HACS

1. В HACS открыть **Интеграции**.
2. Открыть меню пользовательских репозиториев.
3. Добавить `https://github.com/NikaSir/ha-nikas-access` как **Integration**.
4. Установить **NikaS Access**.
5. Перезапустить Home Assistant.
6. Открыть **Настройки → Устройства и службы → Добавить интеграцию**.
7. Найти **NikaS Access** и подтвердить добавление.
8. После перезагрузки интерфейса открыть пункт **Доступ** или маршрут `/dashboard-access-v1/home`.

До слияния PR тестовая установка выполняется вручную из ветки PR; точный порядок приведён в [docs/PHONE_ACCEPTANCE.md](docs/PHONE_ACCEPTANCE.md).

## Проверки

```bash
npm test
```

Проверки контролируют регистрацию и владение маршрутом, allowlist сервисов, обязательное подтверждение, блокировку повторной отправки, источник положения секционных ворот, отсутствие оптимистической индикации, автономность bundle и требования NikaS v1.17.

## Границы репозитория

Этот репозиторий не содержит и не изменяет:

- основную панель «Дом»;
- старые YAML-панели;
- панель «Действия»;
- маршруты других интеграций.
